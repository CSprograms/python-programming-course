# UCAM11I Python Programming: Session Viewer

A static web app for browsing all 75 sessions of the **UCAM11I Python Programming**
course (BCA Section 1, Sri Sankara Arts and Science College (Autonomous), Enathur).
It shows each program's code with syntax highlighting, its description, the
documented sample output, and a "Try also" hint where there is one.

- 75 sessions in 5 units: Introduction to Python (1–15), Flow Control (16–30),
  Functions and Exception Handling (31–45), Strings and Lists (46–60),
  Tuples and Dictionaries (61–75)
- 230 programs: session programs, workout programs, assignments and class tests
- Seminar and Student Discussion sessions show a short note in place of code
- Search by title, keyword, code text or session number
- Works on desktop and mobile; plain HTML/CSS/JavaScript with no framework

## Run locally

Python 3.9 or newer is required; no other installs are needed.

```bash
python build_data.py                              # regenerate the data
python -m http.server 8000 --directory web-app    # serve the site
# open http://localhost:8000
```

(Use `python3` in place of `python` on Linux/macOS.) Open the site through the
local server, not by double-clicking `index.html`: browsers block `fetch()` of
the data file from `file://` pages.

## Adding or editing a program

1. Put the file in `Session_Programs/Session_NN/` named `Program_K_Short_Title.py`.
2. Start it with a docstring in the course format:

   ```python
   """
   Session 1 - Program 3: Print Banner (Workout)

   Print a banner with the word PYTHON between two rows of asterisks.

   Sample Output:
   **********
   * PYTHON *
   **********

   Try also:
   Change the word to your name.
   """

   print("**********")
   ```

   - The first line becomes the header; the text after the colon is the title.
   - A header containing "Assignment" or "Class Test" marks the session type.
   - `Try also:` is optional and must follow a blank line.
3. Run `python build_data.py` and check the page locally.
4. Commit the `.py` file **and** `web-app/data/sessions.json`, then push.

Netlify runs `build_data.py` on every deploy as well, so the live site always
matches `Session_Programs/`. Committing the JSON keeps the local viewer in sync.

## Deployment

The site deploys through Netlify's Git integration: each push to `main` is
